# Hue Beat Controller

Philips Hue Bridge API v2와 Entertainment 스트리밍을 이용해 2대의 Bridge와 16개 전구로 음악 조명 연출을 만드는 로컬 프로그램입니다. 공식 SDK에 의존하지 않습니다.

## 공식 개발 방향

최종 구조는 다음과 같습니다.

`음원 사전 분석 → 자동 조명 악보 초안 → 모의 전구 검토·수정 → 확정 악보 → 2대 Bridge Entertainment 출력`

실시간 분석값으로 즉흥적으로 전구를 계속 바꾸는 방식은 최종 제품 경로로 사용하지 않습니다. Beat, Downbeat, Onset과 구간 후보는 분석 데이터로 저장하고, 실제 출력은 사용자가 검토·확정한 조명 악보를 기준으로 실행합니다.

구현 원칙과 앞으로의 순서는 [공식 구현 방향 및 앞으로 계획](docs/OFFLINE_SHOW_IMPLEMENTATION_PLAN.md)을 참고하세요.

## 연결 구조

`음원/분석 프레임 → A/B 논리 위치 계산 → 전구 소속별 분배 → Bridge 1/2 Entertainment`

Hue 앱은 Bridge와 전구를 최초 등록할 때만 필요합니다. 실제 제어 중에는 이 프로그램이 Hue Bridge에 직접 HTTPS 요청을 보냅니다.

## 실행

1. Hue Bridge 2대와 PC를 같은 공유기에 연결합니다. 일반 Bridge는 공유기와 LAN 케이블로 연결합니다.
2. Hue 앱에서 전구를 두 Bridge에 최대 10개씩 나누어 등록하고 두 IP를 확인합니다. 좌우 한 쌍을 같은 Bridge에 배치하면 쌍 단위 동기화에 유리합니다.
3. `start.cmd`를 더블 클릭하거나 터미널에서 다음을 실행합니다.

   ```powershell
   cd D:\Philips\HueBeatController
   dotnet run
   ```

   `start.cmd`의 서버 창은 조명을 제어하는 동안 닫지 마세요. 종료할 때는 해당 창에서 `Ctrl+C`를 누릅니다. 이미 5188 포트에서 실행 중이면 기존 서버 PID를 표시하고 브라우저만 엽니다.

4. 브라우저에서 `http://127.0.0.1:5188`을 엽니다.
5. Bridge 1과 Bridge 2를 각각 중앙 버튼을 누른 뒤 30초 안에 인증합니다. 기존 단일 Bridge 설정은 Bridge 1로 그대로 유지됩니다.
6. `현장 전구 배치`에서 `찾기`로 실제 전구를 점멸시키고 L1·R1처럼 이름을 정리합니다. 같은 Bridge 안에서는 드래그나 ↑↓ 버튼으로 순서를 맞추고, `배치 확인`으로 빨강→주황→노랑→초록→파랑→남색→보라→핑크 위치를 확인합니다. 여러 전구를 옮길 때는 카드 아래의 `그룹 이동`을 눌러 체크박스를 열고, 전구를 선택한 뒤 대상 Bridge 이동 버튼을 누릅니다. 대상 Bridge 검색은 한 번만 실행됩니다.
7. Bridge 1과 Bridge 2를 각각 8대로 맞춘 뒤 `8+8을 음악 A/B로 자동 배치`를 누르면 Bridge 1은 왼쪽 A, Bridge 2는 오른쪽 B 그룹에 현장 배치 순서대로 들어갑니다. 자동 배치 후에도 Entertainment 그룹에서 순서를 수동으로 바꿀 수 있습니다.
8. 일반 모드의 `상시 미디어아트`에서 Bridge 1·Bridge 2·둘 다를 선택해 레인보우/밝기/색상 흐름을 웹으로 미리 보거나 실제 Entertainment 영역으로 실행할 수 있습니다. 음악 연출이나 싱크 보정을 시작하면 상시 연출은 자동 정지합니다.
9. 최초 한 번 Python 3.12 환경에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-offline-analysis.ps1`을 실행합니다. 패키지와 모델 설치에는 인터넷이 필요하며 이후 분석은 로컬에서 실행됩니다.
10. `음원 사전 분석`에서 WAV/MP3를 선택합니다. 완료 후 분석 검토 화면으로 이동합니다. 이 단계에서는 실제 전구를 켜지 않습니다.
11. 검토 화면에서 Downbeat와 클라이맥스 경계를 확인하고 `연출 저장`을 누릅니다. 자동 후보가 맞아도 한 번 저장해야 실제 출력 목록에서 사용할 수 있습니다.
12. 메인 음악 모드의 `사전 분석 연출 재생`에서 음원·분석 버전을 고른 뒤 `연출 불러오기`를 누릅니다. `웹 모의 전구만 재생`이 기본 ON이므로 먼저 음악과 모의 전구를 확인합니다.
13. 현장 전구 테스트는 음악 A/B 그룹에 배치한 전구와 실제 소속 Bridge의 Entertainment 영역이 일치하는지 확인한 다음 미리보기 체크를 해제하고 오디오 재생을 누릅니다. 한쪽 그룹만 있는 임시 테스트도 가능하며 빈쪽은 꺼진 상태로 표시됩니다. 양쪽 모두 배치한 경우 전구 수를 같게 맞춥니다. 이 단독 출력은 `사전 분석 연출 재생`에서만 지원하며, 아래의 기존 `2대 스트리밍 연결` 버튼은 여전히 좌우 쌍을 요구합니다. 일반 구간의 `밝기 물결`은 기본 OFF이며 ON/OFF로 비교할 수 있습니다.

## 키오스크 피아노

- **관람객 화면**은 `/piano/`입니다. HueBeat 관리 화면과 분리된 전체 화면 연주 페이지이며 Bridge·전구 설정 버튼은 없습니다. 이전 `/piano.html` 주소도 새 화면으로 이동합니다.
- **운영 설정**은 HueBeat의 음악 모드 → **피아노 운영 · 전구별 음계 배치**에서 합니다. 전구마다 `위치 찾기`로 현장 위치를 확인하고 도·레·미·파·솔·라·시·높은 도 또는 미사용을 선택합니다. 여러 전구에 같은 음을 지정해도 됩니다. 음악 A/B 순서와 짝은 바뀌지 않습니다.
- 초기 설정에는 `A/B 순서를 음계로 복사`를 사용할 수 있습니다. 이후 전구별로 수정하세요. 각 Bridge에서 지정한 전구가 포함된 Entertainment 영역을 선택한 뒤 `실제 전구 출력 허용`과 `음계 소리 사용`을 설정하고 저장합니다. 같은 영역의 미지정 전구는 연주 중 소등하며 영역당 최대 10개를 유지합니다.
- 중앙의 큰 8건반은 C4~C5(도레미파솔라시도)입니다. 왼쪽 C3~B3, 오른쪽 D5~C6까지 22개의 자연음 건반을 연주할 수 있습니다. 색은 빨강·주황·노랑·초록·파랑·남색·보라·빨강입니다. 옥타브가 달라도 같은 음계 전구에 연결되며 C3/C4는 기본 도, C5/C6는 높은 도에 연결됩니다.
- 관람객은 `터치하여 연주하기`만 누르면 됩니다. 실제 출력이 허용돼 있으면 장비에 연결하고, 허용이 꺼져 있으면 화면·합성음으로 연주합니다. 운영자의 `전구 없이 화면 시험` 링크(`/piano/?preview=1`)는 출력 허용과 무관하게 항상 미리보기입니다. 멀티터치·슬라이드와 가운데 음역의 키보드 `A S D F G H J K`를 지원합니다.
- 피아노 설정은 `data/piano-settings.json`에 별도로 저장하며 음악 설정 저장이나 재분석으로 덮어쓰지 않습니다. 설정을 저장하면 진행 중인 피아노 세션을 종료하고 다시 시작할 때 적용합니다. 운영 패널을 새로 열어도 관람객 연주를 자동 종료하지 않습니다.
- 손을 떼면 약 0.18초 감쇠하며 짧은 입력은 최소 0.08초 점등합니다. 마지막 프레임 이후 1초가 지나면 서버가 소등하고, 입력 갱신이 2초 넘게 끊기면 세션을 정리합니다. 오래된 페이지의 종료 요청은 다른 연주에 영향을 주지 않습니다.
- 별도 키오스크 PC에서는 서버를 `dotnet run -- --urls http://0.0.0.0:5188`로 실행하고 같은 네트워크에서 `http://서버IP:5188/piano/`를 엽니다. 기본 실행은 localhost 전용입니다. 서버의 인증 없는 장비 제어 API도 노출되므로 현장 전용 네트워크에서만 사용하고 인터넷에 포트를 공개하지 않습니다. Windows 방화벽과 브라우저 강제 키오스크 실행·시작 프로그램 등록은 현장 설치 단계에서 설정합니다.

## 음악 분석과 재생목록

- Beat This 1.1.0 / final0에서 Beat·Downbeat 시각을, librosa에서 Onset·음량·대역 에너지를 추출합니다. 고정 BPM이나 4박 위상으로 마디를 다시 만들지 않습니다.
- WAV/MP3, 모노·스테레오, 0.1초~10분, 최대 512MB를 지원합니다. 한 번에 한 곡을 분석하며 최대 실행 시간은 15분입니다.
- `analysis-review.html`에서도 음원 추가가 가능합니다. 완료된 곡은 목록에서 다시 열고, 분석 중 새로고침하면 같은 탭에서 작업 확인을 이어갑니다.
- `data/offline-projects/<음원 해시>`에 공통 재생 WAV, 분석 revision, 별도의 연출 수정본을 저장합니다. 재분석은 새 revision을 만들며 기존 분석·악보를 덮어쓰지 않습니다. 기존 악보는 해당 분석 버전을 선택해 다시 엽니다.
- 모델의 원시 시각은 `rhythm.beatsSec`, `rhythm.downbeatsSec`에 그대로 보존합니다. 모의 연출은 이 데이터를 사용하며 A/B 같은 인덱스를 좌우 쌍으로 표시합니다(최대 8쌍).
- 이전 `data/tracks` 음원은 `새 방식으로 분석`으로 가져올 수 있습니다. 기존 파일은 보존하며, 과거 분석을 자동 업그레이드하거나 재생하지 않습니다.
- 분석 검토 화면 자체는 Hue에 출력하지 않습니다. 저장한 클라이맥스 구간과 같은 분석 revision은 메인 음악 모드에서 모의 전구·Entertainment로 재생할 수 있습니다. 현재 저장하는 연출 수정은 클라이맥스 구간뿐이며 Cue별 편집·잠금 기능은 아직 없습니다.
- 다른 PC에서는 분석 환경을 다시 설치하고 `data/offline-projects`를 복사하세요. [Beat This 라이선스 고지](docs/THIRD_PARTY_NOTICES.md)를 함께 보존하세요.

## Entertainment API 테스트

1. 음악 모드에서 A/B 전구를 8개씩 배치합니다.
2. `Bridge별 Entertainment 영역 등록`에서 A/B 그룹의 전구를 실제 소속 Bridge별로 자동 분리해 각각 새 영역으로 등록합니다.
3. 두 영역을 선택하고 `2대 스트리밍 연결`을 누릅니다.
4. 서버는 같은 목표 시각을 사용해 한 프레임을 두 Bridge에 나눠 예약합니다. 한쪽 스트림이 끊기면 좌우가 따로 재생되지 않도록 두 스트림을 모두 중지합니다.
5. 테스트가 끝나면 `연결 종료`를 누릅니다.

Hue의 10개 제한은 Bridge별 Entertainment 영역에 적용됩니다. A/B 그룹을 섞어 배치해도 각 Bridge 소속 전구가 10개 이하면 총 16개를 좌우 8쌍으로 제어할 수 있습니다.

## 현재 버전의 범위

- Bridge 2대 인증, 통합 전구 목록, 연결 상태와 실제 소속 Bridge 표시
- Bridge별 전구 순서·이름·배치 색상 관리 및 선택한 여러 전구의 일괄 이전
- Bridge 1/2의 전구를 음악 A/B 논리 배열로 복사하고 최대 8쌍으로 배치
- Bridge별 Entertainment 영역 등록, 2개 DTLS-PSK 스트림 연결과 공통 목표 시각 프레임 전송
- 음악 없이 동작하는 Bridge별/양쪽 상시 미디어아트와 동일·대칭·16개 연속 레인보우 웨이브
- Beat This와 librosa를 이용한 WAV/MP3 사전 분석 및 Beat·Downbeat·Onset·대역 에너지 원본 보존
- 음원 해시별 재생 WAV, 분석 revision, 사용자 연출 수정본 분리 저장
- 분석 후보를 종류별로 비교 재생하는 검토 화면과 전구 없이 확인하는 A/B 모의 전구
- 마디 첫 박자 기반 누적 점등, 클라이맥스 준비·암전·전체 펀치 모의 연출
- 자동 클라이맥스 후보를 검토·수정·저장하고 기존 분석 revision을 다시 여는 기능
- 저장된 사전 분석 revision과 클라이맥스 구간을 메인 음악 모드에서 선택하고 같은 Downbeat 프레임으로 웹 모의 전구·실제 Entertainment에 출력하는 경로
- 일반 구간의 선택적 밝기 물결 ON/OFF(기본 OFF, 세 번째 8마디 누적 순환에서만 적용)
- 설정과 인증키는 `data`에 로컬 저장하고 Git에서는 제외

현재 분석 검토 화면은 완성된 공연용 Cue 편집기가 아니며, 메인 음악 모드의 Hue 재생도 현장 장비에서 최종 검증이 필요합니다. 다음 단계는 클라이맥스 구간 외의 Cue별 악보 형식과 편집·잠금 기능을 구현하는 것입니다.
