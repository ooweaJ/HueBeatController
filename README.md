# Hue Beat Controller

Philips Hue Bridge API v2를 직접 호출해 컬러 전구를 임의 그룹으로 묶고 음악 박자에 따라 색상을 바꾸는 로컬 테스트 프로그램입니다. 공식 SDK에 의존하지 않습니다.

## 연결 구조

`음원/분석 프레임 → A/B 논리 위치 계산 → 전구 소속별 분배 → Bridge 1/2 Entertainment`

Hue 앱은 Bridge와 전구를 최초 등록할 때만 필요합니다. 실제 제어 중에는 이 프로그램이 Hue Bridge에 직접 HTTPS 요청을 보냅니다.

## 실행

1. Hue Bridge 2대와 PC를 같은 공유기에 연결합니다. 일반 Bridge는 공유기와 LAN 케이블로 연결합니다.
2. Hue 앱에서 전구를 두 Bridge에 최대 10개씩 나누어 등록하고 두 IP를 확인합니다. 좌우 한 쌍을 같은 Bridge에 배치하면 쌍 단위 동기화에 유리합니다.
3. `start.cmd`를 더블 클릭하거나 터미널에서 다음을 실행합니다.

   ```powershell
   cd D:\Philips\HueBeatController
   dotnet run
   ```

   `start.cmd`의 서버 창은 조명을 제어하는 동안 닫지 마세요. 종료할 때는 해당 창에서 `Ctrl+C`를 누릅니다. 이미 5188 포트에서 실행 중이면 기존 서버 PID를 표시하고 브라우저만 엽니다.

4. 브라우저에서 `http://127.0.0.1:5188`을 엽니다.
5. Bridge 1과 Bridge 2를 각각 중앙 버튼을 누른 뒤 30초 안에 인증합니다. 기존 단일 Bridge 설정은 Bridge 1로 그대로 유지됩니다.
6. `현장 전구 배치`에서 `찾기`로 실제 전구를 점멸시키고 L1·R1처럼 이름을 정리합니다. 같은 Bridge 안에서는 드래그나 ↑↓ 버튼으로 순서를 맞추고, `배치 확인`으로 빨강→주황→노랑→초록→파랑→남색→보라→핑크 위치를 확인합니다. 필요하면 연결된 전구를 다른 Bridge 칸으로 옮겨 실제 등록도 이전할 수 있습니다.
7. Bridge 1과 Bridge 2를 각각 8대로 맞춘 뒤 `8+8을 음악 A/B로 자동 배치`를 누르면 Bridge 1은 왼쪽 A, Bridge 2는 오른쪽 B 그룹에 현장 배치 순서대로 들어갑니다. 자동 배치 후에도 Entertainment 그룹에서 순서를 수동으로 바꿀 수 있습니다.
8. `1분 테스트 시작`으로 활성 그룹의 색상 순환과 응답 속도를 먼저 확인합니다.
9. 음원 파일을 선택하면 곡 전체의 실제 타격과 강약을 분석한 뒤 `data/tracks`에 음원과 분석 결과가 저장됩니다.
10. 이후에는 `분석된 음악` 재생목록에서 재생 버튼만 누르면 음악과 조명 연출이 함께 시작됩니다.

## 음악 분석과 재생목록

- 전체 BPM은 참고값으로만 사용하며 조명 시점은 실제 파형의 강한 타격에서 선택합니다.
- 조명 명령은 최소 1초 간격입니다. 약한 도입부는 자동으로 2~4초 간격까지 줄이고, 고조 구간은 최대 1초마다 실행합니다.
- 선택된 타격 강도에 따라 색상 팔레트 이동 폭도 달라집니다.
- 음원 원본과 분석 JSON은 `data/tracks`에 함께 저장되므로 서버 재시작 후에도 재생목록이 유지됩니다.
- 다른 PC로 옮길 때는 `HueBeatController` 폴더 전체를 복사하면 재생목록과 그룹 설정이 함께 이동합니다.

## Entertainment API 테스트

1. 음악 모드에서 A/B 전구를 8개씩 배치합니다.
2. `Bridge별 Entertainment 영역 등록`에서 A/B 그룹의 전구를 실제 소속 Bridge별로 자동 분리해 각각 새 영역으로 등록합니다.
3. 두 영역을 선택하고 `2대 스트리밍 연결`을 누릅니다.
4. 서버는 같은 목표 시각을 사용해 한 프레임을 두 Bridge에 나눠 예약합니다. 한쪽 스트림이 끊기면 좌우가 따로 재생되지 않도록 두 스트림을 모두 중지합니다.
5. 테스트가 끝나면 `연결 종료`를 누릅니다.

Hue의 10개 제한은 Bridge별 Entertainment 영역에 적용됩니다. A/B 그룹을 섞어 배치해도 각 Bridge 소속 전구가 10개 이하면 총 16개를 좌우 8쌍으로 제어할 수 있습니다.

## 현재 버전의 범위

- Bridge 2대 인증, 전구 목록 통합 및 소속 Bridge 표시
- 일반 Hue API v2 명령을 전구 소속 Bridge로 자동 분배
- 임의의 전구를 A~E 논리 그룹으로 매핑
- Bridge 실제 응답 여부와 전구별 Zigbee 연결 상태 표시
- 수동 제어/박자 연출 탭 분리
- 전체 전원, 마스터 밝기, 전체 RGB 색상 제어
- 전구마다 개별 켜기·끄기, 밝기 슬라이더, RGB 색상, 식별 테스트
- 원형 색상판과 R/G/B 숫자 입력이 연동되는 확인/취소 모달
- A~E 박자 그룹별 전구 목록, 선택 추가, 개별 제거 및 수동 패널과 양방향 동기화
- 4/4 테스트 리듬에 맞춰 60초간 그룹별 색상을 순환하는 자동 테스트
- 빈 그룹·그룹 미지정 전구·연결 불가 전구 제외 및 전구 수에 따른 테스트 BPM 자동 제한
- Bridge별 Hue Entertainment 영역 조회·등록, DTLS-PSK 스트림 2개 연결/종료, 공통 목표 시각 프레임 전송
- Entertainment 연결 시 기존 A~E 그룹과 음악 분석을 그대로 스트리밍 모드로 전환
- 수동/박자 전환 시간 0~1000ms 설정과 즉시 0ms 버튼
- 그룹별 색상, 밝기, 전환 시간 설정
- 음원 전체의 BPM 참고값, 실제 타격, 구간별 에너지를 결합한 가변 조명 타임라인
- 분석한 음원과 타임라인을 보존하는 로컬 재생목록, 구간 탐색 재생 및 삭제
- 설정 인증키는 `data/hue-settings.json`에 로컬 저장되며 Git에서 제외

이 버전은 일반 API의 가능성과 현장 지연을 측정하기 위한 MVP입니다. 많은 전구에서 시각적 어긋남이 확인되면 다음 단계로 Scene/Grouped Light 최적화 또는 Entertainment API 모드를 추가합니다.
