# 렌더러 v9: 타격과 잔광 일관성

## 이번 변경

- 평평한 입력과 작은 흔들림은 중역/고역 피크로 처리하지 않는다.
- 120ms 이내 후보는 킥(기존 저음 중심 타격점), 중역, 고역 순서로 우선한다.
- 이벤트를 미래 프레임에서 먼저 소비하지 않는다. 실제 이벤트 이후 첫 50ms 프레임에 위치와 최대 펀치를 함께 적용한다.
- 첫 타격은 A1/B1이다. 각 타격은 자기 위치와 강도를 저장하고 그 위치에서 감쇠한다.
- 밝기를 더해 포화시키기보다 배경과 타격의 최대값을 합성한다. 강조색도 잔광에 따라 기본색으로 돌아온다.
- 웹/실제 출력은 같은 색 혼합 함수를 사용한다. 새 프레임에는 추가 70ms 전환을 붙이지 않는다.
- 작은 변화의 자동 구간 경계는 장면/색을 유지한다. 평균 에너지 변화 0.18 이상 및 이전 장면 4초 유지, 또는 사용자가 유형을 수정해 확인한 경계에서 장면을 바꾼다. 이는 음악적 구조를 보장하는 분류기가 아닌 보수적인 임시 규칙이다.
- 구간 분류만으로 암전/전체 플래시를 만들지 않는다. 수동 또는 확인된 Cue만 실행한다.
- 기존 분석 v9/v10 음악을 선택하면 원본 음원 재분석 없이 렌더러 v9로 갱신한다. 더 오래된 분석은 기존 업그레이드 흐름을 따른다.

## 검증과 다음 단계

자동 회귀 검사: 일정 입력의 가짜 피크, 첫 쌍, 미래 이벤트 소비, HIT와 펀치 일치, 이전 위치 잔광, 박자 경계의 강조 위치 유지, 중복 후보 우선순위, 불확실한 구간 유지, 수동 Cue, 1/2/5쌍, 결정적 재생.

현장 확인은 아직 필요하다. 같은 곡의 같은 구간에서 다음을 확인한다.

1. 뚠 소리와 밝아지는 순간이 맞는가?
2. 지속음에서 불필요하게 이동하거나 반짝이지 않는가?
3. 이전 타격의 잔광이 같은 전구에서 사라지는가?
4. 자동 구간이 너무 오래 유지되면 해당 시간대와 파형 구간 유형을 기록한다.

다음 단계는 이 결과로 판단한다. 악기 분리/FFT 분석기는 이번에 교체하지 않았다. Kick/Snare/High 표기는 정확한 악기 인식 결과가 아닌 기존 특징 기반 역할이다. 프레임 양자화(최대 약 50ms)와 실제 전송 지연은 별도로 남아 있다.
