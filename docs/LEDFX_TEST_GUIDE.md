# LedFx 원본 엔진 테스트

현재 화면은 원본 효과 비교 대신 **HueBeat 음악 연출**을 사용한다. 최신 사용법은 [HUEBEAT_SHOW.md](HUEBEAT_SHOW.md)를 참고한다. 아래 원본 RGB 비교 절차는 이전 단계의 기록이다. 설치 방식은 동일하다.

## 이번 버전의 범위

2026-09-16: 원본 Energy/Bar/Power 외에 **Power — 색상 정리 (단색)** 비교 효과 추가. 원본 Power의 픽셀별 최대 RGB 값(기존 Hue 밝기 명령값)을 유지하면서 색만 교체한다. 분석 결과와 비교 절차는 [LEDFX_RESPONSE_COMPARISON.md](LEDFX_RESPONSE_COMPARISON.md) 참고.

`experiment/ledfx-engine`의 독립 실험 패널이다. 기존 분석·음원·설정을 변환하지 않는다.
원본 LedFx의 실시간 오디오 반응을 먼저 비교하며, 곡 전체의 클라이맥스를 미리 이해하는 공연 구성 엔진은 아니다.

음원 재생 → 브라우저 PCM → 로컬 LedFx 분석/효과 → DRGB UDP → 컨트롤러 → 웹 A/B 미리보기 / 선택적 Hue Entertainment.

## 실행

1. Python 3.12(이번 PC 검증 버전) 또는 3.13과 Git, .NET 10 SDK를 준비한다.
2. 프로젝트 폴더 PowerShell에서 `./setup-ledfx.ps1`을 한 번 실행한다. 설치에는 인터넷이 필요하다.
3. `start.cmd`로 컨트롤러를 실행하고 Chrome 또는 Edge에서 `http://127.0.0.1:5188`을 연다.
4. 최상단 **LedFx 원본 엔진 실험 → 엔진 연결**을 누른다.
5. 저장된 음원을 선택하거나 로컬 파일을 고르고 **음악 재생**을 누른다. 기존 분석 데이터를 다시 만들 필요는 없다.
6. Energy / Bar / Power를 바꾼 뒤 **효과 적용**으로 비교한다. 처음에는 실제 Hue 출력 체크를 끈 채 확인한다.
7. 실제 출력은 A/B 배열을 같은 수로 맞추고 Entertainment 영역에 해당 전구들을 넣은 다음 체크한다. 선택한 쌍 수와 그룹 수가 같아야 한다. 같은 인덱스를 A/B에 복제한다.

새 로컬 파일은 브라우저에서만 읽으며 이 패널에서 재생목록에 저장하지 않는다. 저장된 음원 선택은 기존 음원 파일을 읽기만 한다.
다른 PC로 옮길 때 `tmp/ledfx-venv`는 재사용하지 말고 설치 스크립트를 다시 실행한다.
`data/ledfx-engine`은 독립 LedFx 설정/로그 경로이고, 기존 `data/tracks` 등과 함께 Git에서 제외된다.

## 주의점

- 로컬 PC 한 곳에서 한 테스트 탭만 연결한다. WebSocket도 `127.0.0.1:8888`에 연결하므로 다른 PC에서 서버 웹에 접속하는 구성은 지원하지 않는다.
- HTTP/WS 8888, UDP 21325는 루프백 전용이다. 외부 방화벽 포트를 열 필요가 없다.
- 실시간 분석이므로 음악 출력 이후 분석·렌더링·전송 지연이 있다. 기존 사전 분석용 오디오/조명 보정값은 이 패널에 적용하지 않는다.
- 원본 프레임은 약 30Hz 목표, 웹 폴링과 Hue 요청은 지연에 따라 더 낮아진다. 실제 전구가 이 속도로 정확히 따라가는지는 현장 검증이 필요하다.
- Energy는 주파수 대역 에너지에 따라 막대 길이를 정수화한다. 전구 수가 적거나 에너지가 낮으면 전체 0이 될 수 있다. 1쌍은 Power로 시험한다. 원본 알고리즘은 수정하지 않았다.
- 빠른 점멸 주의. **일시 정지/실험 정지** 시 미리보기는 검게 하고, 이 실험에서 사용한 Hue 스트림은 끈다. 브라우저 강제 종료/네트워크 단절 시 실제 전구의 마지막 상태는 별도 확인해야 한다.
- 기존 연출 버튼/보정 테스트와 동시에 실행하지 않는다. 기존 음원 플레이어 재생 시 실험을 정지한다.
- 컨트롤러가 시작한 LedFx 프로세스만 정상 서버 종료 시 함께 종료한다. 이미 따로 실행 중인 LedFx는 종료하지 않는다.
- 내장 브라우저의 기본 오디오 재생 버튼에서 한 차례 충돌이 발생했다. 별도 **음악 재생** 버튼으로 실제 음원 재생·RGB 변화·정지 검증을 완료했다. 실제 스피커 청취와 현장 지연 검증은 남아 있다.

## 원본과 어댑터의 경계

- 브라우저는 48kHz 오디오를 채널 평균으로 모노 PCM16 변환하여 초당 60블록을 전송한다. 대역/박자/색상은 직접 분석하지 않는다.
- LedFx 원본 `audio_stream_data_v2` → 원본 오디오 분석 → 원본 Energy/Bar/Power를 사용한다.
- LedFx UDP DRGB `[2, timeout, R,G,B,...]`의 실제 픽셀을 받는다. 화면용 미리보기 이벤트의 밝기 보정은 사용하지 않는다.
- 웹은 받은 RGB를 그대로 표시한다. Hue 어댑터는 RGB 최대값을 밝기로 분리하고 색상을 정규화한다. 물리 전구의 색역/감마/밝기와 화면은 시각적으로 완전히 같다고 보장하지 않는다.
- 마이크 없는 PC에서 원본 기본 장치 탐색 오류가 확인되어 공식 설정 API로 WEB AUDIO 장치를 먼저 지정하는 우회만 추가했다. LedFx 소스 파일 수정 없음.
- 쌍 수 변경 시 이 어댑터 전용 `huebeat-1`~`huebeat-5` 장치를 교체한다. 이 이름은 실험용 예약 이름으로 사용한다.
