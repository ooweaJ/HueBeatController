# 사전 분석·편집형 연출 — 진행 기록

2026-09-16 / `experiment/ledfx-engine`

## 지금 어디까지 왔나

승인한 구현 계획의 **0단계 보존 기반과 1단계 비교 도구**, 그리고 사용자가 요청한 **웹 분석 검토 화면**을 구현했다. 기존 전구 연출은 교체하지 않았다. 분석기의 채택, 실제 음악 정확도 및 연출 품질 합격은 아직 아니다.

| 단계 | 현재 상태 | 다음 통과 조건 |
| --- | --- | --- |
| 0 보존·계약 | 기존 설정·음원·편집 데이터 백업, 해시 검증, 독립 프로젝트/분석 revision 구현 | 다곡 평가 세트 확보. 악보 편집 계약은 3단계에서 구현 |
| 1 분석기 비교 | librosa/Beat This 별도 설치, 예시 1곡 실행, 클릭 확인 음원 생성 | 수동 정답 주석과 여러 곡 비교 후 후보 결정 |
| 2 분석 검토 화면 | 읽기 전용 파형·후보별 클릭 재생·탐색·확대·반복 구현 | 곡별 검토 및 누락/중복 주석·저장 기능은 후속 작업 |
| 3–6 악보·구간·출력·배포 | 미착수 | 앞 단계 검증 뒤 순서대로 진행 |

## 실제로 확인한 결과

- 기존 저장 파일 5개(설정 2개, LedFx 설정, 음원, 곡별 분석·편집 JSON)를 별도 백업했다. 분석 뒤 원본 해시가 동일했다. 로그·임시 파일은 보존 대상에서 제외했다.
- 같은 음원을 48kHz 스테레오 재생 자산으로 분리했다. 시간 원점은 원본의 0초이며 앞부분 무음을 자르지 않았다.
- 모델은 공식 `final0`의 SHA-256을 고정했다. 모델이 없거나 해시가 다르면 실패하며, 분석 중 Python 소켓 연결을 차단했다. 기존 LedFx 가상환경은 변경하지 않았다.
- 재분석은 새 폴더로만 저장한다. 기존 `data/tracks`나 자동 업그레이드 API를 호출하지 않는다. 임시 `.pending` 폴더는 완료 결과로 취급하지 않는다.
- 두 번째 독립 실행에서도 특징 배열과 박자·타격 시각 배열이 정확히 같았고 두 분석 버전이 모두 남았다. 백업과 비교 자료는 .NET 빌드/배포 수집 대상에서도 제외했다.
- 기본 제한은 WAV/MP3, 모노/스테레오, 10분·512MiB이다. 실행 래퍼는 15분·작업자 메모리 4GiB 제한 및 Ctrl+C 취소를 제공한다. 현장용 처리 속도 보장은 아니다.

### 예시 1곡의 실행 수치 — 정확도 점수가 아님

길이 228초의 기존 예시 WAV, 이 개발 PC의 CPU 기준 첫 실행이다. 패키지 다운로드/설치 시간과 클릭 오디오 내보내기 시간은 포함하지 않는다. 후보별 시간에는 import·초기화 비용이 포함된다.

| 항목 | librosa 0.11.0 | Beat This 1.1.0 / final0 |
| --- | ---: | ---: |
| 소리 시작 후보 | 683개 | 제공하지 않음 |
| Beat 후보 | 369개 | 406개 |
| Downbeat 후보 | 제공하지 않음 | 104개 |
| 후보 분석 소요 | 약 17.9초 | 약 6.8초 |

전체 약 26.5초, 작업자 최대 메모리 약 1.28GiB. 5분 곡이나 다른 PC의 벤치마크로 일반화할 수 없다. 서로 다른 박자 수는 비교할 필요가 있다는 뜻이지, 어느 쪽이 맞다는 뜻이 아니다. 예전 120 BPM 표시를 정답으로 가정하지 않았다.

공통 음원과 라이브러리 캐시가 준비된 두 번째 실행은 약 10.1초, 최대 약 1.13GiB였다. 첫 실행과 캐시 재사용 실행을 혼동하지 않는다.

### 원본 음원에서 발견한 변환 위험

예시 파일은 32bit float WAV이고 peak 약 1.366, 전체 채널 샘플 중 1,368개가 ±1을 넘었다. 이를 정수 PCM으로 변환하면 잘릴 수 있다. 계획의 ‘24bit 정수 PCM 공통 자산’ 후보 대신 **48kHz stereo float32 WAV**로 보존했다. 정규화나 이득 변경을 하지 않았다. 최종 오디오 출력의 헤드룸은 별도 검토해야 한다.

클릭 확인용 WAV는 원음 복사본을 낮춘 뒤 클릭을 더한 파생 파일이다. 공연에 쓸 공통 재생 자산이 아니며 원음을 바꾸지 않는다.

## 자동 검증과 아직 검증하지 않은 것

13개 자동 시험 통과: 44.1/48kHz의 시간 원점·앞 무음 보존, 프로젝트 재사용/변조 감지, float peak 보존, 역위상 상쇄 대응, 무음, 합성 타격 4개 검출, 시각 범위·중복·단위 계약, 새 버전 전용 저장, 백업 무변경, 모델 손상, 일대일 주석 평가, 미검토와 빈 정답 구별.

기존 .NET Release 빌드 성공(경고·오류 0). 웹 JavaScript는 변경하지 않았다.

**미검증:** 실제 음악 타격/박자 정답, 여러 곡의 범용성, 악센트 선택, 조명 미감, 클라이맥스 인식, MP3 디코딩의 실제 파일 비교, 장시간/취소/메모리 초과의 장애 주입, 실제 전구 지연. 단위 테스트 통과로 이 항목들을 합격 처리하지 않는다.

## 웹에서 확인하기 — 2026-09-16 추가

`http://127.0.0.1:5188/analysis-review.html`에서 확인한다. 컨트롤러 상단의 **새 음악 분석 검토 열기** 링크로도 이동할 수 있다. 새 API가 필요하므로 다른 PC에서 Git pull을 받았다면 기존 서버를 종료하고 `start.cmd`로 다시 켠다.

1. 새 분석 결과가 있는 곡과 분석 버전을 선택한다. 기존 음원 목록을 자동 재분석하거나 저장하지 않는다.
2. **소리 시작(librosa)** 또는 **박자(Beat This)**를 선택하고 재생한다. 선택된 종류의 선만 파형에 보이고 클릭음도 해당 시각에만 나온다.
3. 마디 첫 박자(Beat This)·비교용 박자(librosa)도 선택할 수 있다. 모델 분석을 하지 않은 버전에서는 해당 버튼이 비활성화된다.
4. 곡 전체 위치 슬라이더나 파형 클릭으로 이동하고, 확대 범위 5/10/20/30초를 고른다.
5. 반복 시작·끝을 초 단위로 지정하거나 현재 확대 구간을 사용한다. 후보를 전환해도 현재 곡 위치를 유지한다. 반복 범위 밖으로 탐색하면 반복이 해제된다.
6. 음악·클릭 음량을 따로 조절하거나 클릭만 끄고 비교한다. 다른 탭으로 이동하면 검토 재생을 일시 정지한다.

음악과 클릭은 Web Audio의 같은 AudioContext에서 두 버퍼를 같은 시각·오프셋으로 시작한다. 반복도 두 버퍼의 동일한 시작·끝을 사용하며 브라우저 프레임 반복문으로 클릭을 발사하지 않는다. 기존 전구·오디오 보정값은 이 상대 비교에 적용하지 않는다. 화면 재생선과 실제 소리 사이의 출력 지연은 별개이므로 음악과 클릭 소리를 기준으로 판단한다.

API는 완료된 `offline-projects` 폴더만 읽는다. 임시·잘못된 ID·링크 경로는 제외하고 공통 음원 SHA-256도 확인한다. 원본과 파형 길이가 다르면 재생을 막는다. 읽기 전용 GET 경로만 추가했으며 Hue 제어·기존 분석 업그레이드와 연결하지 않았다.

Git에는 음원·분석 결과를 올리지 않으므로 다른 PC에서는 `data/offline-projects` 폴더를 별도로 복사하거나 해당 PC에서 분석해야 한다. 빈 목록에는 웹 안내가 표시된다. 웹에서 분석 실행·큐 수정·주석 저장은 아직 제공하지 않는다.

웹 검증: JS 핵심 로직 21개 자동 시험(분리된 후보, 누락 모델, 손상 데이터, 44.1/48kHz 클릭 위치, 반복 시계, 경계·개수, 수동 구간과 클라이맥스 프레임), API 통합 점검, 브라우저에서 재생/정지·후보 전환·탐색·반복·클라이맥스 경계를 확인했다. 이는 음악적 정확도를 귀로 평가해 합격했다는 뜻이 아니다.

## 파일 위치와 실행법

컨트롤러 폴더의 PowerShell에서 실행한다. 첫 설치만 인터넷이 필요하며 Python 3.12를 사용한다. 원래 `setup-ledfx.ps1`과 별개다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-offline-analysis.ps1
$analysisPython = '.\tmp\offline-analysis-venv\Scripts\python.exe'
& $analysisPython tools/offline/run.py snapshot
& $analysisPython tools/offline/run.py compare 'C:\음원\곡.wav' --review-audio
& $analysisPython tools/offline/run.py verify 'data\offline-backups\백업ID'
& $analysisPython -m unittest discover -s tests -p test_offline_analysis.py -v
```

`--baseline-only`는 사용자가 명시했을 때만 모델 없이 librosa를 비교한다. 실패할 때 자동 선택되는 대체 경로가 아니다.

```text
data/
  tracks/                         기존 파일, 새 도구에서는 읽기만
  offline-backups/<백업ID>/       개인 설정 포함: 공유·Git 업로드 금지
  offline-projects/<음원해시>/
    manifest.json                 원본·재생 해시, 변환 및 시간 원점
    playback.wav                  분석과 재생의 공통 시간축용 복사본
    analyses/<분석ID>/
      analysis.json               특징 + 후보별 박자·시작 시각
      summary.json                개수·성능, 정확도는 미측정 표시
      listening.json              확인용 파일과 원곡 시작 시각
      review/*.wav               클릭을 겹친 확인용 오디오
    shows/<분석ID>/<버전>.json    사람이 표시한 연출 구간의 불변 저장본
```

분석 JSON에는 조명 큐·장비 ID·인증키를 넣지 않는다. 원본 분석과 사람이 고친 악보를 합치는 기능은 아직 없다. 같은 음원의 재분석은 이전 폴더를 덮어쓰지 않는 새 분석 ID를 만든다.

`docs/offline-evaluation-template.json`을 개인 데이터 폴더로 복사해 평가곡과 주석을 기록한다. `onsetsSec`, `beatsSec`, `downbeatsSec`는 각각 검토한 배열만 추가한다. 누락된 필드는 미검토, 빈 배열은 검토했으나 사건 없음이다.

```powershell
& $analysisPython tools/offline/evaluate.py 'data\offline-projects\해시\analyses\ID\analysis.json' 'data\labels.json'
```

## 도구와 라이선스 확인 범위

- [librosa](https://github.com/librosa/librosa/blob/main/LICENSE.md): ISC. 비교 기준으로 0.11.0을 고정했으며 최신 버전이라는 뜻이 아니다.
- [Beat This](https://github.com/CPJKU/beat_this): 코드와 공개 모델 MIT 안내. Beat/Downbeat 후보만 사용하며 DBN/madmom은 설치하지 않았다.
- CPU torch/torchaudio 2.8.0, Python 3.12. 전체 설치 버전은 `tools/offline/requirements-win-py312.lock.txt`, 각 결과에는 실제 환경을 기록한다.
- final0 SHA-256: `8c328b45f59d8dd3dff219253ff6a8d6482be57d0133a29140e2febbf8eb8331`.
- 분석 실행 자체는 로컬 전용이다. 완전 무인터넷 신규 설치 패키지와 전체 전이 의존성 라이선스 동봉/배포 감사는 아직 완료하지 않았다. 모델·가상환경·음원·분석 JSON·개인 백업은 Git에서 제외한다.

## 작업 재개 메모

### 마디 첫 박자 모의 점등 추가

사용자 청취 피드백: 이 곡에서는 마디 첫 박자 후보가 원하는 점등·색 변경 시각에 가장 가까웠으며, 약 58초에 연속 후보가 어색했다. 전체 곡·다른 곡의 정확도 합격으로 해석하지 않는다.

- 두 저장 분석 버전 모두 57.760초와 58.000초에 후보가 있다(240ms 간격). 주변에는 54.020, 56.000, 60.020, 62.020초 후보가 있다. 어느 쪽이 음악적 정답인지는 아직 확정하지 않았다.
- 검토 화면의 기본 탭을 ‘마디 첫 박자’로 변경하고, 같은 번호 A/B 한 쌍만 고정된 따뜻한 색으로 점등한다. 15ms 상승 후 감쇠하여 600ms에 완전히 꺼진다. 다음 후보에서는 이전 쌍을 즉시 끄고 다음 쌍으로 이동한다.
- 배치는 1~5쌍을 배열 크기로 처리한다. 실제 장비 ID·그룹 순서를 읽거나 바꾸지 않으며 Hue 전송은 없다. 색 변경·클라이맥스 자동 연출은 이번에 추가하지 않았다.
- 시각과 후보 배열에서 매번 전체 프레임을 계산한다. 중간 탐색·반복도 같은 시각에는 같은 결과이며 프레임 카운터를 누적하지 않는다. 일시 정지는 해당 시각의 정지 화면, ‘처음으로 정지’는 전체 소등이다.
- 화면 표시에는 지원되는 브라우저의 오디오 출력 타임스탬프를 사용한다. 브라우저 화면 갱신·실제 전구의 물리 지연까지 정확하게 검증했다는 뜻은 아니다.
- ‘짧은 간격 후보 검토’는 주변 간격 중앙값의 35%보다 짧은 간격을 검토 대상으로만 표시한다. 원본·클릭·모의 점등에서 후보를 자동 삭제하지 않는다. 해당 행의 ‘이 구간 반복’으로 앞뒤 문맥을 들을 수 있다. 특정 곡의 58초 예외를 연출 코드에 넣지 않았다.
- 기존 테스트에 소등·감쇠, 가까운 후보 교체, 동적 쌍 수, 탐색 결정성, 간격 경고와 원본 보존 등 6개 자동 시험을 추가했다.

이번 결과를 기존 웹 자동 업그레이드에 연결하지 말 것. 구현된 검토 화면으로 후보를 비교하고, 후속으로 주석 평가를 준비한다. 새 연출 알고리즘을 선택하기 전에 ‘타격 후보가 틀렸는가’와 ‘맞는 후보를 너무 많이 연출하는가’를 따로 확인해야 한다.

### 수동 클라이맥스 구간 모의 연출 추가

마디 첫 박자를 조명 전환 시각으로 사용하되, 클라이맥스 여부는 아직 자동 추정하지 않는다. 웹에서 곡을 들으며 시작·끝을 직접 표시한다.

- 클라이맥스 밖에서는 기존처럼 A/B 같은 번호의 한 쌍만 점등하고 0.6초 동안 감쇠한다.
- 클라이맥스 안에서는 모든 모의 전구를 75%로 유지하고, 마디 첫 박자마다 코랄·청록·골드·보라를 순환한다. 밝기 펀치와 실제 Hue 전송은 이번 범위가 아니다.
- 구간은 곡·분석 버전별 `shows/<분석ID>/<버전>.json`에 저장한다. 분석 JSON을 수정하지 않으며 저장할 때마다 새 버전을 만든다. 재분석 결과에 기존 연출을 자동 복사하지 않는다.
- 저장 전 화면 변경은 ‘미저장’으로 표시한다. 다른 화면이 먼저 저장했으면 기존 파일을 덮어쓰지 않고 충돌을 알린다. 범위 밖·중첩·0.1초 미만 구간과 손상된 저장본은 거부한다.
- 프레임은 재생 시각과 마디 첫 박자 배열에서 결정하므로 탐색·반복 후에도 같은 시각은 같은 색이다. 클라이맥스 종료 직후 직전 후보가 한 쌍 점등으로 재생되는 현상도 막았다.

다음 청취 검토에서는 먼저 사람이 표시한 구간 경계가 맞는지 확인한다. 구간 안 색 변경이 맞고 밝기감만 부족할 때에만 별도 밝기 펀치를 설계한다. 이 단계의 합격 여부를 자동 클라이맥스 분류 정확도로 해석하지 않는다.

### 자동 클라이맥스 초안과 마디 내부 동작 추가

역할을 분리했다. 마디 첫 박자는 장면의 기준점이고, 일반 박자와 소리 에너지는 장면 안의 움직임이다.

- 약 11.6ms 간격의 RMS, 저·중·고역 파워, onset strength를 robust percentile과 로그 압축으로 0~1 범위에 정규화한다. Beat This의 일반 박자 주변 onset과 에너지를 합쳐 박자별 펀치 강도를 만든다.
- 마디 첫 박자 사이를 한 단위로 묶어 에너지 50%, 세 대역의 충만도 22%, onset 상위값 18%, 박자 밀도 10%로 구조 점수를 계산한다. 높은 점수가 6초 이상 지속되는 구간을 자동 클라이맥스 후보로 삼고 경계는 마디 첫 박자에 붙인다.
- 자동 후보는 분석 원본을 바꾸지 않는 재계산 가능한 초안이다. 저장본이 없는 곡에서만 기본 적용하고, 저장본이 있으면 사람의 편집을 우선한다.
- 일반 구간에서는 마디 첫 박자마다 현재 A/B 쌍을 바꾼다. 다음 마디 전까지 일반 박자는 같은 쌍의 밝기만 펀치하며, 에너지가 낮으면 분석기에 박자가 있어도 펀치를 억제한다.
- 클라이맥스에서는 전체 전구를 기본 점등하고 일반 박자에 밝기를 올렸다가 감쇠한다. 색은 마디 첫 박자에서만 변경한다. 프레임은 여전히 재생 시각에서 순수 계산하므로 탐색·반복 후에도 결정적이다.
- 현재 샘플 곡의 자동 초안은 74.060~104.040초와 140.060~202.040초였다. 이는 한 곡의 모의 검토 결과이며 다른 곡의 범용 정확도 합격을 뜻하지 않는다.

다음 판단은 사용자의 청취 검토다. 자동 구간 경계가 틀리면 분류 점수부터 고치고, 경계는 맞지만 동작이 어색하면 박자 펀치·감쇠만 고친다. 두 문제를 다시 한 임계값으로 섞지 않는다.

### 클라이맥스 경계와 일반 구간 타격 보정

사용자 청취 결과, 샘플 곡의 첫 자동 클라이맥스 진입은 한 마디 늦었고 두 번째 진입은 두 마디, 종료는 한 마디 늦었다. 또한 클라이맥스 밖에서 고정 박자마다 깜빡이는 동작은 실제로 들리는 ‘뚠!’보다 지나치게 많았다. 곡의 초 단위를 예외 처리하지 않고 다음 두 판단을 분리했다.

- 자동 진입 임계값을 넘은 뒤에는 바로 앞 마디가 이미 충분히 강한지 확인해 최대 두 마디까지 되짚는다. 낮은 에너지 경계는 넘지 않는다.
- 음량이 계속 커도 고역 에너지와 onset 상위값이 동시에 급락하면 음악적 이완으로 보고 해당 마디에서 클라이맥스를 끝낸다. 낮은 잔향만 남은 별도 구간은 클라이맥스로 다시 만들지 않는다.
- 일반 구간은 Beat This의 고정 박자표를 점등 명령으로 사용하지 않는다. 정규화한 onset 65%와 저음 급상승 35%를 합친 국소 피크 중 상위 분포·돌출도·최소 450ms 간격을 통과한 실제 타격만 A/B 한 쌍을 펀치한다.
- 클라이맥스 안에서만 일반 박자를 전체 밝기 펀치에 사용하고, 마디 첫 박자는 색 전환에만 사용한다.

샘플 곡의 자동 후보는 `72.040~104.040초`, `136.040~200.040초`로 보정되었다. 이전 초안은 각각 `74.060~104.040초`, `140.060~202.040초`였다. 이 수치는 청취 피드백과 일치하는지 확인하는 회귀 사례이며, 다른 곡의 범용 정확도 합격을 뜻하지 않는다. 다음 검토에서는 일반 구간의 실제 타격 누락·과검출과 클라이맥스 두 경계를 별도로 평가한다.
