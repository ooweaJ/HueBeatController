# 음악 분석 및 조명 연출 개발 로드맵

## 목표

특정 음원의 시간대를 하드코딩하지 않고, 서로 다른 곡에서도 음악의 흐름을 따라가는 Hue Entertainment 연출을 만든다.

분석과 연출을 분리한다.

```text
음원 분석 → 공통 음악 특징 데이터 → 음악 상태/이벤트 판정 → 조명 악보 → Entertainment 재생
```

분석이 끝난 음원은 공통 특징 데이터를 보존한다. 조명 패턴을 개선할 때 원본 음원을 매번 다시 분석하지 않고, 저장된 특징 데이터에서 조명 악보만 다시 생성할 수 있게 한다. 분석 데이터 형식이 추가되는 경우에만 해당 음원을 한 번 재분석한다.

> 2026-09-11 무대 조명 레퍼런스 조사 결과, 순간 피크 중심 개발을 중단하고 `Beatgrid/Phrase → 패턴 프리셋 → Cue/Timecode → FFT 보조 변조` 구조로 전환한다. 상세 근거는 [음악 연동 무대 조명 레퍼런스 조사](STAGE_LIGHTING_REFERENCE_RESEARCH.md)를 참조한다.

## 개발 원칙

- 한 단계에서 분석 기준과 조명 패턴을 동시에 크게 바꾸지 않는다.
- 화면에서 분석 결과를 먼저 검증한 뒤 실제 전구 동작에 사용한다.
- 모든 곡에서 같은 특징을 추출하되, 임계값은 곡 안의 상대값과 지역 평균으로 정규화한다.
- 짧은 사건과 긴 음악 구간을 분리한다.
- A/B 그룹은 같은 수의 전구를 사용하고, 같은 배열 인덱스를 좌우 한 쌍으로 취급한다.
- 사용자가 테스트한 결과와 문제가 발생한 시간대를 단계별 기록에 남긴다.

## 공통 분석 데이터 목표

### 순간 특징

- 전체 음량(RMS)과 Peak
- 저음, 중음, 고음 에너지
- 음색 변화량(Spectral Flux)
- 소리 시작점(Onset)과 강도
- 무음 가능성

### 리듬 특징

- 참고 BPM과 신뢰도
- 실제 Beat/Onset 시각
- 강박(Downbeat) 후보
- 타격 밀도와 타격 간격

### 화성 특징

- Chroma 12차원 분포
- 이전 구간과의 화성 유사도
- 화음 변화량과 안정도

### 장기 구조 특징

- 장기 에너지와 상승/하락 추세
- 새로운 구간 가능성(Novelty)
- 반복 구간 유사도
- 음악 구간 경계와 구간별 강도

## 기본 조명 문법

첫 구현 범위는 아래 세 동작으로 제한한다.

1. `HOLD`: 음악 상태가 유지되면 현재 전구와 색을 유지한다.
2. `PULSE`: 같은 상태에서 타격이 발생하면 현재 전구의 밝기만 순간 상승시킨다.
3. `STEP`: 화음 변화 또는 확정된 구간 변화에서만 다음 A/B 쌍으로 이동하고 색을 바꾼다.

이 세 동작이 검증된 뒤 `ACCUMULATE`, `ALTERNATE`, `WAVE`, `EXPAND`, `FULL_PUNCH`, `BLACKOUT`, `DECAY`를 조합한다.

## 활성 로드맵

### R1 — Beatgrid 검증

- [ ] Beat 위치와 마디 첫 박자(Downbeat) 후보 생성
- [ ] 전체/10초 상세 파형에 Beat와 Downbeat 분리 표시
- [ ] Beatgrid 시작점 앞/뒤 보정
- [ ] BPM 절반/두 배 교정

완료 기준: 음악을 들으며 박자선과 마디 첫 박자가 안정적으로 맞는 것을 확인한다.

### R2 — Phrase 분할과 편집

- [ ] Intro/Main/Bridge/Outro 구간 초안 생성
- [ ] 구간 경계 이동·분할·유형 변경
- [ ] Beat 또는 Bar 위치에 경계 스냅

완료 기준: 순간 파형 크기가 아니라 곡의 프레이즈 단위로 연출 구간이 유지된다.

### R3 — 8/16마디 패턴 프리셋

- [ ] 프리셋마다 Look, 공간 이동, 밝기 envelope 정의
- [ ] A/B 배열 크기에 맞춘 패턴 자동 변형
- [ ] 프레이즈별 프리셋 지정

완료 기준: 같은 패턴이 다른 곡과 다른 전구 수에서도 마디에 맞춰 동작한다.

### R4 — FFT 보조 변조

- [ ] 저·중·고역 Gain과 Attack/Release
- [ ] 진입/이탈 임계값 분리
- [ ] 선택된 패턴의 밝기·효과량만 실시간 변조

완료 기준: 음원 반응이 장면을 임의로 바꾸지 않고 현재 연출을 자연스럽게 강조한다.

### R5 — Timecode 조명 악보

- [ ] 프레이즈, 패턴, 중요 Cue를 곡별 악보로 저장
- [ ] 암전·전체 펀치 등 중요 Cue 수동 편집
- [ ] 오디오 시간과 현장 싱크값으로 확정 악보 재생

완료 기준: 같은 음원을 재생하면 항상 같은 결과가 나오고 중요 장면이 정확히 맞는다.

## 이전 실험 단계와 완료 기록

아래 단계는 기술 기준선과 실패 원인을 보존하기 위한 기록이다. 2단계 이후의 기존 `HOLD/PULSE/STEP` 계획은 활성 로드맵 R3의 패턴 내부 동작으로 흡수한다.

### 0단계 — 기준선 고정

- [x] 음원 원본과 분석 JSON 저장
- [x] 실제 음원 시간을 기준으로 조명 타임라인 재생
- [x] A/B 그룹 배열 크기에 따른 동적 좌우 쌍 매핑
- [x] 오디오/조명 수동 싱크 보정
- [x] 본 로드맵 작성

완료 기준: 현재 동작을 재현할 수 있고 이후 변경 목적을 문서로 추적할 수 있다.

### 1단계 — 분석 진단 화면

- [x] 전체 음량 파형 표시
- [x] 저음 곡선 표시
- [x] 감지된 타격 시각 표시
- [x] 재생 위치 표시
- [x] 색상 범례와 분석 버전 표시
- [x] 파형 클릭 시 닫을 수 있는 대형 분석 모달 표시
- [x] 저음 후보와 최종 조명 타격을 분리 표시
- [x] 현재 재생 위치 주변 10초 상세 파형 표시

완료 기준: 음악을 들으면서 놓친 타격과 잘못 감지한 타격을 화면에서 구분할 수 있다.

사용자 테스트:

- 들리는 `뚠!`과 타격 표시가 같은 위치인지 확인
- 표시됐지만 조명이 반응하지 않는 지점 기록
- 소리는 있는데 타격 표시가 없는 지점 기록

### 2단계 — HOLD/PULSE 분리

- [ ] 타격이 없는 동안 현재 위치와 색상 유지
- [ ] 같은 음악 상태에서 발생한 타격은 위치 이동 없이 밝기만 펀치
- [ ] 기본 밝기, 펀치 밝기, 복귀 시간을 데이터로 분리

완료 기준: 초반의 지속음에서 전구가 불필요하게 이동하지 않고, 실제 타격에서만 같은 전구가 반응한다.

### 3단계 — 화성 변화와 STEP

- [ ] Chroma 또는 대체 화성 특징 추출
- [ ] 화성 유사도와 변화량 저장
- [ ] 짧은 흔들림을 제거하는 유지시간과 히스테리시스 적용
- [ ] 확실한 화성 변화에서만 다음 좌우 쌍으로 이동

완료 기준: 같은 음색/화음은 유지되고 음악적으로 다른 부분에서 위치와 색상이 바뀐다.

### 4단계 — 장기 구간 분류

- [ ] 장기 에너지, 타격 밀도, 변화도를 함께 계산
- [ ] INTRO/VERSE/BUILD/BREAK/CLIMAX/OUTRO 구간 초안 생성
- [ ] 최소 유지시간과 진입/이탈 조건 적용
- [ ] 파형 위에 구간 표시

완료 기준: 클라이맥스의 순간적인 음량 하락 때문에 초반 패턴으로 되돌아가지 않는다.

### 5단계 — 조명 악보 생성

- [ ] 분석 결과와 조명 악보 데이터 분리
- [ ] HOLD/PULSE/STEP 이벤트를 재생 전에 확정
- [ ] 그룹 크기가 바뀌면 분석 데이터는 유지하고 조명 악보만 다시 생성
- [ ] 같은 음원은 매번 같은 연출 결과 생성

완료 기준: 재생 도중 즉흥적으로 모드를 재판정하지 않고 저장된 시간순 이벤트를 정확히 실행한다.

### 6단계 — 확장 패턴

- [ ] ACCUMULATE
- [ ] ALTERNATE
- [ ] WAVE
- [ ] EXPAND
- [ ] FULL_PUNCH
- [ ] BLACKOUT
- [ ] DECAY

완료 기준: 기본 세 동작의 안정성을 해치지 않고 구간별 패턴을 교체할 수 있다.

### 7단계 — 편집과 현장 검증

- [ ] 구간 경계 이동
- [ ] 타격 추가/삭제
- [ ] 패턴 수동 교체
- [ ] 수정된 조명 악보 저장
- [ ] 여러 장르와 현장 장비에서 반복 테스트

완료 기준: 자동 분석의 초안을 사람이 짧은 시간 안에 공연용으로 보정할 수 있다.

## 현재 다음 작업

분석 v7의 저음 후보 조정을 잠시 중단한다. 다음 구현은 레퍼런스 조사에 따른 R1 Beatgrid 검증 화면이다. Beatgrid와 마디 첫 박자를 파형에 표시하고, 시작점과 BPM 절반/두 배 오류를 사용자가 보정할 수 있게 한다. 이 그리드가 검증된 뒤 Phrase 분할과 패턴 프리셋으로 진행한다.
