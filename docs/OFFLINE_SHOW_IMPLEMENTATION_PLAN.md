# HueBeat 공식 구현 방향 및 앞으로 계획

이 문서는 HueBeatController의 유일한 공식 제품 방향이다. 이전 LedFx 실시간 효과 실험, 곡별 임계값 조정, 과거 렌더러 버전은 앞으로의 구현 판단 기준으로 사용하지 않는다.

## 1. 최종 목표

공연 전에 음원을 전체 분석하고 편집 가능한 조명 악보를 만든다. 웹 모의 전구에서 음악과 함께 확인하고 사람이 어색한 부분을 수정한 뒤, 확정한 악보를 공연에서 Philips Hue Entertainment로 재생한다.

`음원 → 사전 분석 → 자동 조명 악보 초안 → 모의 전구 검토·수정 → 확정 악보 → 2대 Bridge Entertainment 출력`

분석기가 재생 중 즉흥적으로 전구를 결정하는 구조는 최종 방식으로 사용하지 않는다. LedFx 실시간 분석은 과거 비교 실험이며 제품의 기준 엔진이 아니다.

## 2. 반드시 분리할 세 영역

### 음악 분석

음원 전체에서 다음 데이터를 각각 추출해 저장한다.

- Beat: 반복되는 음악의 맥박 후보
- Downbeat: 마디 첫 박자 후보
- Onset: 새로운 소리나 타격이 시작된 후보
- RMS·Peak: 전체 음량과 순간 세기
- 저·중·고역 에너지: 대역별 강약과 변화량
- 로컬 템포·안정도: 구간별 박자 변화와 신뢰도
- Chroma·변화량: 화성 및 구간 경계 보조값
- 구간 후보: 도입·일반·빌드업·클라이맥스·브레이크·종료의 초안

Beat, Downbeat, Onset과 조명 Cue는 서로 다른 데이터다. 분석 후보를 그대로 모두 점등 명령으로 사용하지 않는다.

### 조명 악보

분석 결과를 입력으로 받아 시간순 Cue 초안을 생성한다. 사용자가 Cue와 구간을 수정하고 확정본을 별도로 저장한다. 재분석해도 사람이 수정한 악보를 자동으로 덮어쓰지 않는다.

Cue에는 최소한 다음 정보가 포함된다.

- 실행 시각
- 대상 A/B 쌍 또는 전체 전구
- 전원, 밝기, 색상
- 공격·유지·감쇠 시간
- 패턴 종류와 구간 정보
- 자동 생성/사용자 수정/잠금 상태

### 재생과 출력

확정 악보와 음악이 하나의 재생 시계를 사용한다. 같은 음원과 같은 악보는 매번 같은 결과를 내야 한다. 웹 모의 전구와 실제 Hue 출력은 동일한 프레임 계산 결과를 사용하고, 장비 지연 보정만 출력 단계에서 적용한다.

## 3. 구간별 기본 연출 문법

- 도입·일반: 8마디 누적을 유지하며 순환마다 정순 → 역순 → 중앙에서 바깥 → 바깥에서 중앙으로 채운다. 색은 단색 → 새 단색 → 두 색 교차 → 쌍별 여러 색으로 확장하고 먼저 켜진 쌍의 색은 유지한다. 누적 밝기는 약 35.5%에서 60%로 증가한다.
- 클라이맥스 이후는 누적 순서만 처음부터 시작하고 패턴·색 단계는 진행한다. 같은 번호의 A/B는 항상 같은 색·밝기다.
- 8번째 마디: 1박에 전체 점등, 2박까지 유지, 3박에 빠른 감쇠·암전, 4박에 현재 색으로 전체 펀치 후 다음 마디 전에 소등한다. 다음 마디 1박에 새 색으로 1번부터 다시 누적한다.
- 마무리는 실제 Beat 시각을 사용한다. 4/4의 내부 3개 Beat가 없으면 해당 마디 길이의 1/2·3/4 지점을 조명 Cue 보조 시각으로 사용하며 분석 원본은 바꾸지 않는다. 무음 마디나 클라이맥스 진입 시 누적을 중단하고 이후 유효 마디부터 다시 시작한다.
- 무음 판정은 원본 RMS의 마디 내 80백분위가 0.001(-60 dBFS) 이하인지로 판단한다. 곡 전체 대비 상대 에너지로 조용한 도입을 삭제하지 않는다. 점등은 검출된 첫 마디부터 시작하며 마디 후보를 임의로 추가하지 않는다.
- 빌드업: 마디 단위로 점등 범위·밝기·움직임을 점진적으로 증가시킨다.
- 클라이맥스 직전 최대 4개의 연속된 유효 마디는 진입 준비 구간으로 사용한다. 기존 점등 쌍과 색을 유지하며 마지막 마디 전까지 남은 쌍을 채운다. 마지막 준비 마디의 첫 박부터 약 0.2초 동안 빠르게 감쇠한 뒤 클라이맥스 시작까지 암전을 유지한다. 감쇠는 초반에 빠르고 끝에 부드럽게 잦아드는 곡선이며, 진입까지 남은 시간이 짧으면 그 시간의 절반 이내로 줄여 암전을 확보한다. 이 구간에서는 일반 8마디 마무리 펀치를 생략하고 클라이맥스 첫 박을 전체 펀치로 사용한다. 준비 구간이 한 마디뿐이면 이미 켜진 쌍만 감쇠하며 새 쌍을 켜지 않는다. 무음이나 이전 클라이맥스를 넘어 준비 구간을 확장하지 않는다.
- 클라이맥스 시작 시 새 단색과 전체 펀치로 진입한다. 시작이 마디 사이로 수동 지정돼도 해당 확정 구간 시작 시각에 진입하며 분석 원본·구간 경계는 변경하지 않는다.
- 클라이맥스: 박자 직전에는 전체 전구를 짧게 완전 소등하고, Beat 순간에는 대상 전구를 100%로 재점등한 뒤 기본 밝기로 감쇠한다. 박자 사이에는 기본 밝기를 유지한다. 진입 직후 첫 펀치는 준비 구간의 암전→전체 점등을 유지하며, 너무 가까운 다음 Beat의 사전 암전은 생략한다. Downbeat는 주요 색상 전환과 장면 전환에 사용한다. 이 짧은 암전은 사전 분석된 Beat 시각으로만 계산하고 곡별 고정 초를 사용하지 않는다.
- 클라이맥스 안에서는 4마디씩 단색 → 두 색 → 여러 색을 반복한다. 펀치는 2마디씩 전체 → 홀짝 교대로 변경한다. 검출한 클라이맥스 구간 경계는 유지한다.
- 브레이크·종료: 점등 수와 밝기를 줄이고 필요할 때만 명시적인 암전 Cue를 사용한다.

자동 생성 결과는 초안이다. 클라이맥스 시작·종료와 중요한 Cue는 파형에서 사람이 확인하고 수정할 수 있어야 한다.

## 4. 전구와 Bridge 구조

- 논리 연출은 같은 배열 인덱스의 A/B 전구를 한 좌우 쌍으로 취급한다.
- 논리 A/B 그룹과 실제 Bridge 소속은 분리한다.
- 출력 직전에 전구의 실제 소속 Bridge에 따라 프레임을 분배한다.
- Bridge 1과 Bridge 2는 각각 Entertainment 영역 제한을 지킨다.
- 현재 목표 구성은 16개 전구, A/B 8쌍, Bridge 2대다.
- 웹에서 Bridge별 전구 목록, 순서, 이름, 배치 색상을 관리한다.
- Bridge 간 실제 이전은 전구 전원이 켜지고 연결된 상태에서 수행하며, 여러 전구는 한 번의 대상 Bridge 검색으로 일괄 이전한다.

## 5. 현재 구현되어 있는 기반

- Bridge 2대 인증과 전구 목록 통합
- 전구별 실제 Bridge 소속과 연결 상태 표시
- Bridge별 순서, 이름 변경, 찾기, 배치 색상 확인
- 선택 모드 기반 다중 전구 Bridge 일괄 이동
- 8+8 전구를 음악 A/B 논리 배열로 복사하는 초기 배치 기능
- Bridge별 Entertainment 영역과 2개 스트림 출력 기반
- 일반 모드에서 Bridge 1·Bridge 2·둘 다를 선택하는 결정적 상시 미디어아트와 웹/실제 Hue 공통 프레임 계산
- 음원·분석 결과의 로컬 저장 기반
- Beat, Downbeat, Onset과 파형을 비교하는 분석 검토 화면
- 전구 없이 확인하는 A/B 모의 전구 기반
- 웹 WAV/MP3 업로드와 기존 저장 음원의 Beat This 사전 분석 연결
- 원시 Beat·Downbeat를 보존하는 rhythm 데이터와 A/B 8쌍 모의 연출 연결
- 분석 작업 상태 표시, 단일 작업 제한, 실패 처리와 별도 revision 저장
- 도입·일반의 8마디 누적 점등과 마지막 마디 3박 소등·4박 펀치·소등, 순환별 색 변경 모의 연출
- 자동 생성한 클라이맥스 초안을 수정하지 않아도 명시적으로 저장 가능
- 저장한 클라이맥스 구간과 원본 Downbeat revision을 메인 음악모드에 불러와 웹 모의 전구·2대 Bridge Entertainment에 같은 프레임으로 출력하는 경로
- 일반 누적 세 번째 순환에서만 동작하는 선택형 밝기 물결(기본 OFF)
- 공식 화면에서 마이크·LedFx 실시간 실험 진입점을 제거하고 사전 분석 검토 흐름으로 통일

분석 정확도, 자동 구간 판정, 편집 가능한 확정 악보는 아직 완성된 기능으로 간주하지 않는다.

## 6. 앞으로의 구현 순서

### 1단계 — 분석 데이터 검증

- 여러 장르의 합법적으로 사용할 수 있는 음원을 평가 세트로 준비한다.
- Beat, Downbeat, Onset을 음악과 비교 재생하고 누락·중복·오검출을 기록한다.
- 동일한 음원과 분석 설정은 동일한 결과를 생성하도록 버전과 파라미터를 저장한다.
- 현재 샘플 한 곡에만 맞는 임계값은 도입하지 않는다.

완료 기준: 최소 8곡에서 주요 Downbeat와 Onset 후보를 사람이 검토할 수 있고, 3곡은 튜닝에 사용하지 않은 검증용으로 남긴다.

### 2단계 — 조명 악보 데이터 형식

- 분석 결과와 조명 악보를 별도 파일과 revision으로 저장한다.
- Cue 추가·이동·삭제·잠금과 구간 변경 이력을 저장한다.
- 재분석 시 사용자 악보를 보존한다.

완료 기준: 같은 확정 악보를 다시 열었을 때 Cue와 구간이 바뀌지 않는다.

### 3단계 — 자동 악보 초안 생성

- 도입·일반·빌드업·클라이맥스·브레이크·종료 규칙을 구현한다.
- Downbeat를 주요 위치·색상 전환 기준으로 사용한다.
- Beat와 선별 Onset은 현재 장면 안의 밝기 펀치로 제한한다.
- 구간의 최소 유지시간과 진입·이탈 조건을 적용해 장면이 흔들리지 않게 한다.

완료 기준: 지속음에서 불필요하게 전구가 이동하지 않고, 클라이맥스에서 한 쌍만 반복되는 문제가 없다.

### 4단계 — 파형 기반 악보 편집기

- 음악, 파형, 분석 후보, Cue, 구간을 같은 시간축에 표시한다.
- Cue 시각·대상·색상·밝기·감쇠와 구간 경계를 수정한다.
- 자동 초안과 사용자 확정본을 구분하고 되돌리기를 지원한다.

완료 기준: 코드를 수정하지 않고 웹에서 어색한 연출을 공연용으로 보정할 수 있다.

### 5단계 — 결정적 재생과 모의 검증

- 음악 재생 시계를 기준으로 확정 악보를 실행한다.
- 정지·탐색·반복 재생 시 과거 예약과 잔광 상태를 초기화한다.
- 모의 전구와 실제 출력에 같은 프레임을 사용한다.

완료 기준: 같은 구간을 반복 재생하면 동일한 전구·색상·밝기 변화가 나온다.

### 6단계 — 2대 Bridge 현장 출력과 보정

- 한 논리 프레임을 실제 소속 Bridge별로 분배해 두 Entertainment 스트림에 전달한다.
- 오디오 출력 지연과 조명 출력 지연을 별도로 측정하고 최종 출력 오프셋을 계산한다.
- 스트림 한쪽이 끊기면 좌우가 따로 재생되지 않도록 전체 연출을 안전하게 중지한다.

완료 기준: 16개 전구가 음악과 반복 가능한 동기로 재생되고, 현장 재연결 절차가 문서화된다.

### 7단계 — 현장 운영과 배포

- 무인터넷 LAN 환경에서 시작·재연결·정지·복구를 검증한다.
- 설정, 인증키, 음원, 분석, 악보의 백업·복원 절차를 정리한다.
- 안정화 후 Windows 실행 파일 패키징을 진행한다.

## 7. 다음 작업

### 2026-09-21 — 사전 분석 연출을 음악모드에 연결

- 새 현장 피드백: 클라이맥스 밝기 펀치가 약하다. 기존의 기본 밝기 위에 더 밝게 겹치는 방식 대신 Beat 직전 약 0.1~0.17초의 완전 암전 후 Beat에서 대상 전구를 최대 밝기로 재점등한다. 모의 전구와 실제 Hue는 같은 프레임을 사용하며 홀짝 교대와 Downbeat 색 전환은 유지한다. 정지·탐색 시 같은 시각의 프레임이 재현되는지 확인하고 실제 기기에서 빠른 암전이 체감되는지 검증한다.
- 구현·검증: Beat 간격의 최대 40%(최대 170ms)를 사전 암전으로 사용하고, 직후 100%로 점등·감쇠하도록 결정적 프레임 계산을 변경했다. 좌우 모의 프레임과 실제 Hue 전송 명령의 0%→100%, 구간 경계·탐색 재현성을 테스트했다. JavaScript 테스트 8개 파일과 별도 출력 폴더 .NET 빌드 통과. 실제 전구의 체감 암전 길이와 빠른 반복 시 동기·눈부심은 현장 검증 후 조정한다.

- 현장 임시 검증: A/B 중 한쪽만 배치·연결된 경우에도 `사전 분석 연출 재생`의 모의 전구와 실제 Hue 출력이 동작해야 한다. 빈쪽은 꺼진 채 표시하고, 배치된 쪽의 배열 순서와 프레임은 그대로 사용한다. 실제 출력은 해당 전구가 속한 Bridge의 Entertainment 영역만 연결한다. 양쪽이 모두 있으면 기존처럼 같은 수의 좌우 쌍을 요구한다. Bridge별 10개 제한은 그대로 적용한다.
- 한쪽만 있는 동안에도 그쪽 Bridge의 Entertainment 영역을 웹에서 등록·갱신할 수 있어야 한다. 기존 40초 테스트와 2대 동시 연결 버튼의 엄격한 A/B 조건은 유지하고, 사전 분석 연출 재생에만 단독 출력을 허용한다.
- 구현 상태: 사전 분석 연출에서 한쪽 단독 프레임·모의 표시·해당 Bridge만 연결하는 출력을 추가했다. 한쪽 영역 등록도 허용한다. B 단독 슬롯 순서와 빈 A 소등을 단위 테스트로 확인했고, 전체 JavaScript 테스트 및 .NET 빌드를 통과했다.
- 다음 현장 확인: B 그룹의 실제 전구와 Entertainment 영역이 일치하는지 확인한 뒤 `사전 분석 연출 재생`에서 미리보기 체크를 해제해 음악·B 전구 동시 재생과 정지 시 소등을 검증한다. 실제 Hue 장비 검증은 아직 완료되지 않았다.

- 구현: 검토 화면에서 선택한 음원·분석 revision·저장된 클라이맥스 구간을 메인 음악모드에서도 불러온다. 저장본이 없는 자동 후보는 실제 Hue 출력에 사용하지 않고 먼저 검토 화면에서 저장하도록 안내한다.
- 구현: 웹 모의 전구와 실제 2대 Bridge Entertainment 출력은 `analysis-review-core.js`의 동일한 Downbeat 기반 프레임을 사용한다. A/B 같은 번호의 색·밝기를 유지하며 실제 Bridge 소속에 따라 전송 직전에 분배한다.
- 구현: 일반 구간의 밝기 물결은 기본 OFF인 ON/OFF 비교 옵션이다. 켜진 쌍의 기본 밝기를 유지하고 세 번째 8마디 누적 순환에서만 강조를 이동시킨다. 클라이맥스 진입 준비·마무리·클라이맥스에는 적용하지 않는다.
- 검증: 저장된 구간과 같은 분석 revision만 재생하도록 검사하고, 같은 시각의 모의 전구·전송 명령에 같은 색·밝기가 적용되는 단위 테스트를 통과했다. 실제 점등·현장 오디오 동기는 아직 장비에서 확인해야 한다.

- 클라이맥스 준비 구간의 누적 점등과 첫 박자 새 색·전체 펀치를 구현했다. 마지막 준비 마디는 전체 유지에서 첫 박부터 약 0.2초 감쇠 후 전체 소등으로 변경했다. 다음 청취는 동일 곡 1·2절에서 한 마디 암전과 진입 펀치의 대비를 확인한다.
- 검증: JavaScript 구문 검사, 관련 Node 테스트 43개, `dotnet build --no-restore` 통과. 현재 검토 곡은 70.04초와 134.04초부터 0.2초 감쇠한 뒤 각각 72.04초와 136.04초까지 전체 소등하고 각 클라이맥스 시작에 전체 밝기 100%가 되는 것을 프레임 계산으로 확인했다. 이 시각은 검증 기록이며 곡별 하드코딩 규칙이 아니다. 실제 청취·시각 평가는 다음 검토에서 진행한다.
- 마디 첫 박을 주요 연출 기준으로 유지한다. 검출 간격 변화와 연출 가속은 분리한다. 현재 곡의 도입 약 4초 → 이후 약 2초 간격은 템포 변화로 단정하지 않고 Beat·Downbeat 청취 비교로 검증한다.
- Beat This 원본 후보는 보존한다. 여러 곡의 누락·중복·박자 배수 해석 오류를 먼저 기록한 뒤 전처리·후처리 개선을 비교한다. 모델 재학습은 정답 데이터와 평가 세트가 마련된 후 판단한다.
- 추가 연출 후보는 준비 구간의 마디 단위 → 2박 단위 채우기 가속과 선별 Onset의 작은 밝기 강조다. 아직 구현하지 않으며, 모든 소리에 반응시키지 않고 마디 중심 패턴을 유지하는지 모의 검토 후 채택한다.

- 조용한 도입이 상대 에너지 기준으로 제외되는 문제를 원본 RMS 기반 무음 판정으로 수정했다. 낮은 음량의 도입과 실제 무음을 구분하는 회귀 검증을 추가하며, 다음 청취에서는 첫 마디부터 누적되는지 확인한다.

### 순환별 연출 변화 비교

- 모의 프레임에 쌍별 RGB와 패턴 이름을 추가하고, 8마디 누적 순서·색·밝기 상승과 클라이맥스 전체/홀짝 펀치를 구현했다.
- 다음 검토는 동일한 분석·클라이맥스 경계에서 패턴 변화의 빈도와 다색 조합을 청취·시각 비교하는 것이다.

### 추가 패턴 후보 — 미구현

- 우선 비교할 후보는 밝기 물결이다. 켜진 쌍의 낮은 기본 밝기를 유지하면서 1→8 순서로 밝기 강조를 이동한다. 일반 누적 두 순환 뒤 한 순환에만 사용하는 안부터 검토하며, 빈도는 확정하지 않는다.
- 중앙 확산 펀치: 4·5 → 3·6 → 2·7 → 1·8 순서로 밝기 강조를 펼친다. 클라이맥스의 전체·홀짝 펀치 사이에 간헐적으로 사용하는 후보이며 실제 A/B 배치 순서를 기준으로 한다.
- 색 번지기: 마디 첫 박마다 두 쌍씩 새 색으로 바꿔 전체 점등 상태에서도 변화를 만든다. 같은 A/B 인덱스의 색·밝기는 항상 일치시킨다.
- 마디 첫 박 중심의 누적 연출을 유지하고, 추가 패턴은 구간별로 선택한다. 클라이맥스 진입 준비·감쇠·암전이 우선하며 별도 패턴이 진입 타이밍을 가리지 않게 한다. 자동 초안의 Cue로 표현하고 모의 검토 후 확정하는 것이 최종 경로다.

### 곡 마지막 구간 연출 — 다음 설계 과제, 미구현

- 일반 누적이나 클라이맥스 패턴의 반복만으로 끝내지 않고 곡의 마무리에 맞는 별도 엔딩을 설계한다. 파일 끝 시각과 음악의 마지막 타격·잔향·후행 무음을 구분한다.
- 강한 종결 후보: 마지막 주요 타격에 전체 또는 중앙 확산 펀치를 주고 잔향에 맞춰 감쇠한다. 페이드아웃 후보: 움직임과 색 전환을 줄이면서 전체 밝기를 서서히 낮춘다. 조용한 종결 후보: 켜진 쌍을 역순으로 정리하거나 낮은 밝기의 한 색을 유지하다 소등한다.
- 위 방식은 아직 선택하지 않은 비교안이다. 끝부분의 에너지·Onset·마디와 청취를 함께 검토하고, 종료 구간 시작·마지막 강조·감쇠 종료를 악보에서 수정할 수 있도록 설계한다. 모든 곡 끝에 강제 펀치를 넣거나 특정 곡의 초를 하드코딩하지 않는다.
- 다음 검토는 현재 곡 끝부분의 어색한 동작을 기록하고, 강한 종결·페이드아웃·잔향이 긴 곡을 비교하는 것이다. 곡 종료 후 잔광 없이 전체 소등되며 탐색·반복 재생에서도 같은 결과가 나오는지 확인한다.

### 2026-09-20 — 8마디 누적 모의 연출

- 도입·일반의 단일 쌍 점멸을 8마디 누적 → 8번째 마디 내 소등·펀치·소등으로 변경한다.
- 모의 배치 기본값은 A 8개 + B 8개이며 좌우 같은 인덱스를 항상 함께 제어한다.
- 다음 검토는 실제 음원에서 8번째 마디 3·4박의 감쇠 길이와 클라이맥스 전환을 듣고 확인하는 것이다. 확정 Cue 악보와 실제 Hue 출력 연결은 이후 단계다.

### 2026-09-18 — 정식 사전 분석 연결

- 기존 main의 고정 BPM·4박 위상 추정은 새 음원 분석 경로에서 사용하지 않는다.
- Beat This 1.1.0 / final0의 Beat·Downbeat를 로컬에서 추출하고, librosa의 Onset·에너지와 함께 분석 revision에 보존한다.
- 웹 음원 업로드 → 서버의 단일 분석 작업 → 결과 저장 → 파형·모의 전구 검토를 하나의 흐름으로 연결한다.
- 분석 실패 시 기존 추정기로 대체하지 않는다. 분석 원본과 사용자 악보를 덮어쓰지 않는다.
- 논리 모의 배치는 최대 A/B 8쌍을 지원한다. 실제 Bridge별 10개 제한과 출력 분배는 별도다.
- 이 연결은 1단계의 분석 도구 통합이며, 8곡 검증이나 확정 Cue 악보 구현 완료를 의미하지 않는다.

가장 먼저 1단계 분석 검증을 완료한다. 현재 검토 화면에서 Downbeat가 주요 전환 시점으로 유용하다는 결과를 기준으로 삼되, 다른 곡에서도 같은 품질인지 확인한다. 그 다음 조명 악보 스키마를 확정하고 자동 초안 생성으로 넘어간다. 실제 Hue 연출 미세 조정은 악보와 모의 전구가 결정적으로 재생된 이후 진행한다.

## 8. 개발 판단 규칙

- 샘플 한 곡의 특정 초에 맞춘 조건을 제품 규칙에 넣지 않는다.
- 실시간 분석값으로 재생 중 연출 모드를 계속 재판정하지 않는다.
- 분석 실패, 연출 규칙 실패, 출력 지연을 서로 분리해 진단한다.
- 자동 분석의 결과를 정답이라고 표현하지 않는다.
- 실제 전구 없이 모의 전구로 먼저 검증한 뒤 Hue 출력을 켠다.
- 새 기능은 이 문서의 어느 단계에 속하는지 확인하고 구현한다.
- 방향이나 우선순위가 바뀌면 코드보다 먼저 이 문서를 수정한다.
