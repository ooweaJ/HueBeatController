# HueBeat 타격·감쇠 연출 (실험 2: 소리 이벤트 게이트)

## 목표와 경계

Energy에서 좋았던 타격 사이 밝기 대비, Power에서 좋았던 빠른 점등과 감쇠를 참고한 **새 연출**이다. 두 원본 효과의 RGB를 합성하거나 원본 연출과 동일하다고 주장하지 않는다. 특정 곡의 시간/BPM/클라이맥스 표시는 규칙에 사용하지 않는다.

브라우저 음원 PCM → 원본 LedFx 주파수 분석 → `graph_update`의 filtered melbank → HueBeat 타격 후보/모드 판단 → 점등 곡선 → 같은 RGB를 웹 A/B와 Hue Entertainment에 전달한다.

LedFx 원본은 수정하지 않는다. 오디오 분석 구독을 유지하기 위해 내부에 원본 Energy virtual 하나를 실행하지만 **그 RGB는 새 연출에 사용하지 않는다**. 공개 WebSocket 이벤트에는 여기서 필요한 원본 aubio onset 값이 없으므로 **LedFx의 대역 분석을 사용하고, 타격 후보 검출은 우리 규칙**이다. 실제 드럼/악기 분리 또는 비트 정답 판정이 아니다.

참조 소스: 고정 커밋 `87583f9638fbd749bc0953f35334d8d5140c882f`의 `ledfx/effects/melbank.py` (`GraphUpdateEvent`, filtered 출력), `ledfx/api/websocket.py` (subscribe_event), `ledfx/effects/power.py`, `ledfx/effects/energy.py`. 원본 설치/라이선스는 기존 안내서를 따른다.

## 규칙

- 대역 상승 후보 → 소리 이벤트 게이트 → 연출의 세 단계다. 이전 위치만 제한하던 0.8초 규칙은 제거했다. 각 대역이 직전 피크의 55% 아래로 내려온 뒤 충분히 재상승해야 다시 타격을 허용한다. 전체 에너지도 피크의 65% 아래로 회복했거나 135% 이상 새 악센트여야 한다. 최소 간격 120ms는 프레임 중복 방지이며 BPM 타이머가 아니다. 모든 수치는 실험 휴리스틱이고 악기 분리/검증된 범용 onset 모델이 아니다.
- 첫 타격은 1번 쌍에서 시작한다. 전체 펀치 동안에는 위치를 돌리지 않는다. 화면에서 밝기 타격 수와 위치 이동 수를 따로 확인할 수 있다.

- 30~250Hz / 250~2500Hz / 2500~12000Hz로 평균 에너지를 묶고 `x/(1+x)`로 제한한다. 화면 수치는 상대 분석값이며 실제 음량 백분율이 아니다.
- 대역별 양의 에너지 증가량이 적응 임계값(최근 증가량 평균·편차와 최소값)을 넘을 때 타격 후보를 만든다. 일정 세기의 지속음은 매 프레임 재점등하지 않는다.
- 세 대역에서 회복·상승 조건을 통과한 후보 중 가장 강한 것을 사용한다. 채택 시 모든 대역을 잠가 뒤따르는 배음의 중복 반응을 줄인다. 고역만 있는 곡도 사용할 수 있으나 지속음 위의 작은 새 타격을 놓칠 수 있다.
- 한 쌍: 선별된 타격마다 다음 인덱스 A/B 펀치 → 지수 감쇠 → 완전 소등. 기본 반감기 100ms, 400ms 후 완전 소등. 다음 타격이 먼저 오면 이전 쌍은 즉시 소등한다. 항상 켜두는 배경/중앙등과 쌍 사이 중첩은 없다.
- 전체: 모든 쌍에 동시 펀치. 최근 타격 간격을 참고해 감쇠 반감기 70~180ms로 제한한다. 계속 더해서 포화시키지 않고 새 타격마다 곡선을 다시 시작한다. 고정 BPM 타이머는 없다.
- 공격 시간 16ms, 기본 최대 밝기 80%, 단색 살구. 색 연출보다 타격/감쇠를 먼저 평가한다.
- 자동: 최근 2.2초 타격 수, 약 0.7초/8초 에너지 추세, 세 대역에 소리가 함께 분포하는 정도로 한 쌍/전체를 고른다. 저음만 계속 울리는 것을 강한 구간으로 오인하지 않도록 대역 분포 조건을 둔다. 그만큼 대역이 좁은 강한 음악을 놓칠 수 있어 수동 전체 모드와 비교해야 한다. 진입 확인 0.65초, 퇴장 확인 1.8초, 자동 모드 최소 유지 약 2.5초로 잦은 전환을 줄인다. **범용 음악 구간 분류 모델이 아닌 첫 실험 휴리스틱**이다.
- 수동 한 쌍/전체 선택으로 타격 검출 문제와 자동 모드 판단 문제를 분리한다.

## 사용

1. `experiment/ledfx-engine` 최신 버전을 받고 서버 재시작, 웹 강력 새로고침.
2. 상단 **HueBeat 음악 연출 → 분석 엔진 연결**. 기존 LedFx 설치를 재사용한다.
3. 저장된 음원 또는 파일 선택 → 음악 재생. Bridge 없어도 웹 테스트 가능.
4. 먼저 **한 쌍**, 다음 쌍 이동 끔으로 타격/감쇠 확인 → 이동 켬 → 전체 → 자동 순서로 비교하면 원인을 구분하기 쉽다.
5. 타격 민감도, 한 쌍 잔광, 최대 밝기를 조절할 수 있다. 잔광 설정은 다음 한 쌍 펀치부터 반영한다. 설정 변경 후 같은 짧은 구간을 비교한다.
6. 실제 Hue는 A/B 같은 수, 해당 전구가 포함된 Entertainment 영역을 준비하고 체크한다. 총 10개 이하이며 원본 가상 RGB 장치 수와 별개로 우리 배열 크기 1~5쌍을 사용한다.

화면 타격 표시와 카운트로 입력을 확인한다. 색/밝기 수치가 움직이는데 타격 수가 안 늘면 후보 임계값 문제, 타격 수가 늘지만 펀치가 늦으면 오디오/분석/전송 지연 문제로 나눠본다. 화면 검사만으로 청각 싱크를 보장하지 않는다.

검출 클릭음은 기본 꺼짐이다. 켜면 선별 타격마다 짧은 1200Hz 클릭을 스피커에 출력한다. 클릭은 분석 입력으로 되먹이지 않는다. 실제 들리는 악센트와 클릭의 누락/중복을 비교하며, 실시간 분석 지연을 포함하므로 정밀 지연 측정 도구는 아니다. 상승 후보 카운트는 조건을 만족한 프레임 수이며 독립된 소리 개수가 아니다.

## 정지와 제한

- 일시 정지/시킹/쌍 수 변경 시 연출 이력을 초기화하고 이 패널이 쓰던 Hue 스트림을 소등·해제한다.
- 분석값이 600ms 이상 끊기면 출력 0. 재개 시 오래된 타격 이력은 폐기한다.
- 실시간 분석 지연과 네트워크 지연이 있다. 기존 사전 분석 보정값은 미적용. 여러 탭 또는 기존 연출과 동시 사용하지 않는다.
- 갑작스러운 브라우저/PC 종료의 물리 소등은 보장하지 않는다. 실제 조명 최종 상태를 확인한다.
- UI 설정은 이번 단계에서 세션 내 사용이며 새로고침하면 기본값이다. 기존 그룹·음원 데이터는 변경하지 않는다.

- 합성 9개 테스트: 무음, 지속음 및 떨림, 느린 상승, 고역 단독, 250ms 연타와 변속, 한 쌍 비중첩/완전 소등, 자동 모드와 리셋을 검증했다.
- 다음 검증: 서로 다른 실제 곡(잔잔한 곡, 빠른 댄스곡, 지속음 중심 곡, 드럼 없는 곡)을 클릭음으로 청취 대조하고 중복/누락 시각을 기록한다. 현재 실제 음원 자료는 한 곡뿐이므로 다곡 검증은 미완료다. 자동 모드 분류/지속음 전용 연출은 별도 후속 단계이며 이번 수정으로 완성됐다고 보지 않는다.

- 단위 테스트: 지속음 1회 후 소등, 무음, 120 BPM 합성 타격의 펀치 사이 밝기 감소, 고역 단독 타격, 1~5쌍 배열, 자동 모드 진입/퇴장, 데이터 단절/초기화/밝기 0.

- 브라우저 실제 음원 입력과 A/B 미리보기는 확인하며, 실제 전구 싱크·음악적 만족도는 사용자 현장 테스트가 필요하다.
- 이번 WAV의 독립 12초 구간 기록 재생: 초반(8초부터)과 후반(200초부터)은 한 쌍 유지, 강한 비교 구간(188초부터)은 준비 구간 이후 전체 펀치로 전환됨. 타격 후보 수는 각각 31/36/25회이며 악기별 정답과 대조한 수치는 아니다. 한 곡의 이 결과로 범용성을 입증한 것은 아니고, 곡 전체 연속 재생 시의 내부 상태도 다를 수 있다.
- 피드백은 구간 시각과 함께 **타격을 놓침 / 불필요한 타격 / 여운 길이 / 자동 모드 전환 오류**로 나눠 받는다. 시간이 규칙의 조건으로 들어가는 것은 아니다.
